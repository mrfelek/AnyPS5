# Day log, Saturday 24 October 2026

Every step of the test day, in order: what ran, where, why, the numbers, and what came out of it. Times are Polish time (CEST). Numbers are medians over the same game phase; "presents per 10 s" is frames shown per 10 seconds (88 = 8.8 FPS). Machines: Linux desktop (RTX 3080 Ti), AMD mini PC (Radeon 780M, RADV), Windows laptop (RTX A2000). Raw logs stay on the machines; the run pages in [perf-data](../perf-data/) have the full metric sets.

Ground rules for the day: every game run muted; one run per machine at a time; no change judged on FPS alone (CPU per thread, GPU time by pass, cache hits, copies, compiles, waits, RAM and VRAM recorded for every run); a bug confirmed on plain main before a fix is tested; runs shared between investigations instead of re-running a game.

## Summary

- **Wins:** f32 denormal flush fix v2 (Diablo II Resurrected (PPSA03912) menu +26%, GPU 104 -> 74 ms per frame; laptop Hot Wheels garage +4-11%); staging written-only buffers (#7618, D2R gameplay 56 -> 77-85 presents per 10 s for +150-200 MiB VRAM); two of my upstream PRs approved (GameUpdate "no update" for the Hot Wheels crash, Silksong seam on AMD).
- **Upper bound only:** skipping the flush of big buffer bindings gave the Hot Wheels title +17% (unsafe as written).
- **No effect:** 1080p output report (#7814), skipping the indirect argument read, importing the read-back buffer, import page hashing (#10655, Linux), import budget (#7844, AMD), float fix on AMD.
- **Ruled out:** our draw cache relocation patch (verifier abort on AMD), Ghost of Yotei (PPSA26344) GPU path (slower), Yotei memory runaway (only with the shader cache off), Hot Wheels black scenery (cause not found, stopped), frame capture on Linux (Windows only).
- **Conclusion:** enough data. The games are slow because of three design problems, not one bad scene: [structural-analysis.md](structural-analysis.md).

### 12:50 to ~21:00 · Hot Wheels Infinite Rush (PPSA22408) garage, black scenery · AMD mini PC, Windows laptop · ruled out
- **Why:** the garage and race scenery is black on every GPU; find the cause.
- **What:** frame capture on AMD, then 15 trace steps following the GPU culling pass back to its inputs; a capture and 7 replays on the laptop.
- **Result:** frame capture works on Windows only (Linux aborts). The culling pass gets an all-zero visibility mask because one record field stays -1, so every object is culled.
